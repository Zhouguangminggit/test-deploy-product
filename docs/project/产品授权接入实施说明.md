# django-scaffold 产品授权接入实施说明

> 状态：待实施设计。配套中台文档为《产品授权码：中台整体规划》。本说明适用于基于本脚手架交付源码的产品；独立站负责交易后发码，授权中心由中台提供。

## 一、目标和约束

授权开关关闭时保持现有启动体验；开启时用户首次输入产品专属授权码，通过联网验证后绑定一台电脑，并在最近一次成功验证后允许离线 7 天。未经授权、失效或离线超期时显示醒目提示与激活入口。服务器在线体验通过服务器独有配置免检，不占用用户设备数。完整源码可被修改，本方案旨在降低随意传播，不承诺无法破解、不可复制设备指纹或离线即时撤销。

## 二、配置与产品交付

在 `config/settings/base.py` 通过 django-environ 读取配置，`.env.example` 写无密钥示例：

| 配置 | 含义与默认值 |
| --- | --- |
| `LICENSE_ENABLED` | 是否启用，默认 false；交付包必须由产品配置显式设置 |
| `LICENSE_PRODUCT_ID` | 中台产品 ID 的十进制字符串；启用时必填，打包时校验 |
| `LICENSE_SERVER_URL` | 授权中心 HTTP 或 HTTPS 根地址；启用时必填，禁止硬编码实际环境 |
| `LICENSE_PUBLIC_KEYS` | 按 key ID 配置 Ed25519 公钥集合；允许轮换，不含私钥 |
| `LICENSE_BYPASS` | 默认 false，仅体验服务器环境变量设置 true；本地包不能使用 |

启用但缺少产品 ID、有效 HTTP/HTTPS 地址或可信公钥时进入配置错误页面，不静默关闭授权。体验服务器由部署平台注入 `LICENSE_BYPASS=true`，不写入 `.env.local`、产品仓库或 ZIP。生产启动记录不含密钥的免检状态，限制该部署配置的修改权限；本地持源码用户可自行修改配置，不能作为防篡改保证。

当前 `scripts/package.py` 从 `.env.local` 生成 `.env`，同时排除 `.env`、文档、数据库和 `static/css/dist`；新增发布前配置校验，明确将产品级开关、产品 ID、授权地址和公钥写入包内 `.env`，拒绝 `.env.local` 中启用 bypass，不复制签名私钥、服务端密钥、用户授权码、设备标识或租约。排除授权缓存目录、临时文件和历史备份；打包测试解压 ZIP 检查。未授权产品仍明确输出 `LICENSE_ENABLED=false`。不把构建机器缓存带给用户。

授权码是每次交付独立生成的随机值；公钥只验证中台签发的租约，并不决定授权码。一个公钥可验证多个产品，验签后仍须核对租约产品 ID 与本产品一致；中台私钥不进入产品包。HTTP 传输时授权码和设备摘要可能被窃听，响应可能被篡改；签名不能提供传输保密，也不能验证拒绝响应。建议公网使用 HTTPS，HTTPS 必须校验证书，禁止因错误自动降级。

## 三、模块和接入点

- 新增 `apps/licensing/`，注册到 `LOCAL_APPS`，包含设备标识、授权客户端、租约验证及本地缓存服务、表单、函数视图、URL、模板与测试；跨模块调用公开 service，网络调用集中封装。无需新增业务数据库表时，记录无迁移及种子数据的原因，不创建真实授权码种子。
- 将授权中间件放在 `SecurityMiddleware` 后、WhiteNoise 前，以覆盖 Django 经过的动态、静态和媒体请求；确认 ASGI/WSGI 均加载同一配置。中间件只豁免激活页及其 POST、专用内联样式的警示页、必要健康检查；不豁免 admin、业务 API、媒体或通用静态文件。警示页使用内联 CSS，避免依赖被拦截的构建产物；API/非 HTML 请求返回结构化 403 和稳定业务码，不能返回正常业务数据。授权完成后恢复原路径。
- Django 开发服务器可能通过 staticfiles 的外层处理直接提供静态资源，生产反向代理/CDN 也可能绕过 Django；在受保护交付模式下配置或替换外层静态服务，使静态/媒体请求经过相同守卫并用实际 runserver、WSGI 和 ASGI 测试验证。无法保障的独立静态托管不得部署受保护资源。注意所有源码文件仍由用户持有，此措施只控制 HTTP 访问。
- 本地未授权页面突出“产品未经授权、不得二次出售，请尊重作者的知识成果；一经发现，可追究责任，后果自负”，同时给出输入授权码、重试、联网及联系售后的明确指引。启用 CSRF，POST 才允许激活；拒绝将授权码置入 URL、页面回显、日志或错误追踪。

## 四、激活、设备与租约

1. 用户按原方式执行 `python scripts/startup.py`；脚本保留依赖安装、迁移和启动行为，提示浏览器打开本地页面完成激活，不在命令行参数传递授权码。直接运行 `manage.py runserver` 也受统一中间件保护。激活页表单提交到本地服务，本地服务通过配置的 HTTP 或 HTTPS 请求中台 `POST /public/licenses/activate`，产品 ID、授权码、设备摘要随请求体提交；成功后存储授权码及签名租约。
2. 设备摘要在 Windows、macOS、Linux 上使用各系统稳定机器标识，经产品 ID 和固定协议版本做 SHA-256 派生；不上传原始硬件信息。不以 MAC 地址、用户名、IP 或随机安装 ID 单独作为机器标识；取不到稳定标识时明确报错并联系售后，不静默更换算法。系统重装、虚拟机克隆或硬件变更可能影响绑定，由运营重置处理。采集前在页面说明用途。
3. 缓存放在项目根目录专用隐藏目录，限制本机用户访问权限，写入采用临时文件后原子替换；文件中包含用于续验的授权码、签名租约及时间元数据，不纳入 ZIP、日志或 Git。操作系统权限只降低意外泄露，不保证源码持有人无法读取。缓存损坏按未授权处理并要求重新联网激活，不自动清除服务器绑定。
4. 验证服务端 Ed25519 签名、公钥 ID、协议版本、产品 ID、当前设备摘要、签发与到期时间；不信任本地可编辑的有效期。每次请求先使用短期内存缓存避免重复验签，距离最近一次成功在线校验达到 24 小时时触发有超时的在线续验，同进程单飞并跨进程使用锁避免请求风暴；联网失败时仍使用未过期的签名租约。服务明确返回停用、设备不匹配、未绑定或无效码时立即阻断并提示，不使用离线宽限覆盖明确拒绝。客户端遇到限流、超时、网络或服务不可用才可用未过期租约。
5. 记录最近一次观察到的本地时间；检测到时间早于租约签发时间或明显早于上次记录（容忍 5 分钟误差）时要求在线验证，无法联网则阻断。系统时钟和本地状态可被持源码用户篡改，不能视作可靠防篡改机制。时间以 UTC 和服务端签名时间计算。
6. 售后确认后由中台重置绑定，用户在新设备重新激活；旧设备在线校验即失效，断网时旧租约最多剩余 7 天。界面区分无效码、设备数量已满、停用、网络异常、离线过期、配置错误和时钟异常，不披露其他用户信息。

## 五、测试与上线

- 单元测试 HTTP 和 HTTPS 地址、HTTPS 证书校验及无自动降级，并测试设备标识跨平台分支、签名和密钥轮换、错误产品/设备、租约过期和损坏、时钟回拨、文件权限与原子写入；使用假时钟和模拟 HTTP，不调用真实授权中心。
- 集成测试未启用、首次激活、重复激活、第二设备拒绝、重置和停用、24 小时续验、7 天边界、明确拒绝与暂时故障的差异、无缓存断网、并发续验及配置错误。
- 通过真实 runserver、WSGI/ASGI 覆盖前台、admin、API、静态及媒体，以及激活页可用性、CSRF 和免检环境；解压实际交付 ZIP 检查配置与缓存排除。Windows/macOS/Linux 各做一次机器标识及新手启动验收。
- 先合并中台 API 与密钥配置，再接入脚手架并制作试点产品包，独立站完成发码后逐产品启用。历史包和已下载源码不会被自动改造；需要重新打包与通知。故障时恢复授权服务，已有租约仅在签名有效期内工作。

## 六、脚手架实现进度与验收记录（2026-11-11）

已接入授权配置、Ed25519 租约验签、设备摘要、原子本地缓存、联网激活与续验、明确拒绝时阻断、时钟回拨检查、授权中间件与内联激活页面。开发服务器静态文件改为经过 Django 中间件；打包校验授权配置、拒绝免检并排除本地缓存。默认关闭授权；体验服务器免检只接受进程环境变量。本模块无数据库模型、迁移、初始化记录或图片需求，不生成真实授权码。

当前实现仍需完成专项验收，不能据此认定已达到上线标准：尚未覆盖真实 Windows 和 Linux、WSGI/ASGI 与完整中台联调、并发续验压力测试、全部打包边界及真实用户启动验收。当前请求逐次读取并验签缓存，尚未实现短期内存缓存；跨进程锁已有实现但尚未在三平台验证。受保护资源不得由绕过 Django 的反向代理或 CDN 独立提供。
